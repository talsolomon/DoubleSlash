## מה זה בכלל אייג׳נט: הגדרה שלא שמעתם בכנסים

רוב ההגדרות שתשמעו על אייג׳נטים מגיעות ממאמרי מחקר או מכנסי טק, ומסבכות מה שהוא בסופו של דבר פשוט מאוד.

> **AI Agent**: תוכנה שמשלבת מודל שפה עם יכולת לקחת פעולות בעולם האמיתי. המודל חושב, מחליט מה לעשות, מבצע פעולה, רואה מה קרה, וחושב שוב.

זה הכל. Plan, Act, Observe, Plan. שוב ושוב, עד שהמשימה מסתיימת.

ההבדל בין צ׳אטבוט לאייג׳נט הוא פשוט: צ׳אטבוט עונה. אייג׳נט עושה.

כשאתם/ן שואלות את ChatGPT "מה מזג האוויר בתל אביב?", זה צ׳אטבוט. כשיש לכם/ן אייג׳נט שבכל בוקר שולף את מזג האוויר לבד, כותב תקציר, ושולח אותו לווטסאפ שלכם/ן, זה אייג׳נט.

הכלי הוא המפתח. בלי כלים, אין אייג׳נט. יש רק LLM חכם שחי בתוך חלון הקשר שלו ולא יכול לגעת בשום דבר מחוצה לו.

```
עובדה חביבה: מודל שפה גרידא לא יכול לדעת מה השעה עכשיו.
אין לו גישה לשעון. כלי פשוט של get_current_time פותר את זה מיד.
זה ההבדל בין LLM לאייג׳נט.
```

## ארבע שאלות שצריך לענות עליהן לפני שמתחילים

זו הטעות הכי שכיחה. כולם מתחילים מ"אני רוצה אייג׳נט ש..." ואף אחד לא מסיים את המשפט הזה בצורה מדויקת מספיק.

בנו אייג׳נט רק אחרי שיש לכם/ן תשובות ברורות לארבעה דברים:

**מה הטריגר?** מה מפעיל את האייג׳נט? לוח זמנים? אירוע ספציפי (מייל חדש, הודעה בסלאק)? פעולה ידנית שלכם/ן? אם לא יודעות/ים מה מפעיל אותו, הוא לא יפעל.

**מה ה"עשה"?** פעולה אחת, ברורה. לא "נהל לי את החיים". משהו כמו: "קרא כל מייל שמגיע, בדוק אם הוא דורש פעולה ממני, ואם כן, סכם אותו בשלוש שורות ושמור בקובץ."

**מה הגבול?** מה האייג׳נט לא מורשה לעשות. לא מוחק. לא שולח בשמכם/ן בלי אישור. לא גישה לתיקיות X. הגבולות לא מגבילים אתכם/ן, הם מונעים מהאייג׳נט לדפוק לכם/ן משהו ב-3 בלילה.

**מה ה"סיים"?** איך האייג׳נט יודע שסיים? בלי קריטריון סיום ברור, הוא ממשיך לנסות ולנסות, ומוציא לכם/ן כסף על ניסיונות שלא היה צריך לעשות.

ענו על ארבעת אלה לפני שפותחים כלי כלשהו.

## הכלים: מה האייג׳נט יכול לעשות בעולם

כל פעולה שאייג׳נט יכול לעשות בעולם האמיתי עוברת דרך כלי. הנה הקטגוריות:

> **כלי קריאה**: שולף מידע. web search, קריאת קבצים, שאילתות API. האייג׳נט לא יודע מה קורה בחוץ בלי אלה.

> **כלי כתיבה**: משנה מידע. שמירת קבצים, שליחת מיילים, עדכון גיליון. אלה הכלים שדורשים גבולות ברורים.

> **כלי ביצוע**: מריץ פעולות. browser automation, שליחת הודעות, פרסום. עוצמתיים ומסוכנים יותר.

> **כלי זיכרון**: שומר ושולף הקשר בין ריצות. בלי אלה, האייג׳נט שוכח הכל כל פעם מחדש.

הרגל טוב: לכל כלי שנותנים לאייג׳נט, שאלו "מה הכי גרוע שיכול לקרות אם הוא ישתמש בזה בטעות?" אם התשובה מפחידה, הוסיפו שלב אישור לפני הביצוע.

## הזיכרון: החלק שכולם שוכחים לבנות

מודל שפה חי בתוך חלון הקשר שלו. מה שנכנס לחלון, הוא "יודע". מה שיצא, הוא "שכח". בלי שכבת זיכרון, כל ריצה מתחילה מאפס.

שלוש שכבות שצריך להחליט עליהן:

**זיכרון בתוך סשן**: מה האייג׳נט זוכר במהלך ריצה אחת. קיים אוטומטית.

**זיכרון בין סשנים**: מה האייג׳נט זוכר מהפעם הקודמת. לא קיים אוטומטית, צריך לבנות. הפתרון הפשוט: קובץ טקסט שהאייג׳נט קורא בהתחלה ומעדכן בסוף.

**זיכרון מובנה**: חיפוש חכם בזיכרון לפי משמעות. שימושי כשיש הרבה מידע צבור.

90% מהאייג׳נטים לא צריכים יותר מהפתרון הפשוט.

(מאמר נפרד בבלוג בנושא שלוש שכבות הזיכרון של AI)

## הטעות הכי שכיחה: אייג׳נט שעושה הכל

"אני רוצה אייג׳נט שינהל לי את הפרויקטים, ינהל לי את המיילים, יזמין לי פגישות, ויסכם לי ישיבות."

לא. זה לא אייג׳נט. זה ארבעה אייג׳נטים שעדיין לא בנויים.

האנטי-פטרן הזה, ה"God Agent", מוביל לאייג׳נט שלא טוב בכלום. הוא מבולבל, איטי, וכשהוא נשבר, אין לכם/ן מושג איפה.

כלל אצבע: אם אי אפשר להסביר מה האייג׳נט עושה במשפט אחד, הוא גדול מדי.

```
עובדה חביבה: המחקר מראה שאייג׳נטים קטנים וממוקדים מדויקים ב-40% יותר
מאייג׳נטים כלליים שמנסים לכסות הרבה תחומים בו-זמנית.
```

## מה זה Claude Desktop ולמה זה לא סתם צ׳אט

Claude Desktop היא אפליקציה למחשב — Mac ו-Windows — שנראית בהתחלה כמו חלון צ׳אט רגיל. אבל יש בה שתי יכולות שהופכות אותה למשהו אחר לגמרי:

**Projects**: קבוצות שיחה עם הוראות קבועות. אתם/ן כותבות/ים פעם אחת "אתה עוזר/ת הכתיבה שלי, אתה מכיר את הסגנון שלי, אתה עונה תמיד בעברית" — ומאותו רגע, כל שיחה ב-Project הזה מתחילה עם ההוראות האלה. הזיכרון נשמר.

**MCP Servers**: חיבורים שמאפשרים ל-Claude Desktop לגשת לדברים מחוץ לחלון הצ׳אט. קבצים על המחשב, Google Drive, Notion, Slack, ועוד. זה מה שהופך אותה מצ׳אטבוט לאייג׳נט שיכול לעשות דברים.

> **Claude Desktop**: אפליקציה של Anthropic שמאפשרת לעבוד עם Claude ישירות מהמחשב, עם Projects לשמירת הקשר קבוע ו-MCP Servers לחיבור לכלים חיצוניים. לא דורש API key.

ההבדל הגדול מ-Claude.ai: הכל נשמר בין שיחות. Claude יודע מי אתם/ן, מה עשיתם/ן אתמול, ומה הסגנון שלכם/ן. זה לא "שיחה חדשה כל פעם" — זה שותף/ה שמכיר אתכם/ן.

## MCP Servers: כשרוצים שהאייג׳נט יגיע לדברים לבד

Projects הוא הצעד הראשון. MCP Servers הוא הצעד הבא.

> **MCP (Model Context Protocol)**: תקן פתוח שמאפשר ל-Claude Desktop להתחבר לשירותים חיצוניים. כל חיבור נקרא "MCP Server". Anthropic פרסמה MCP servers מוכנים לשימוש לשירותים הנפוצים.

MCP servers פופולריים שעובדים עם Claude Desktop:
**Filesystem**: גישה לתיקיות על המחשב שלכם/ן. Claude יכול לקרוא קבצים, לכתוב קבצים, לחפש.
**Google Drive**: גישה לקבצים ב-Drive.
**Notion**: קריאה וכתיבה לדפים ב-Notion.
**Slack**: קריאת הודעות וכתיבה לערוצים.
**GitHub**: גישה לקוד ולפולים.

הגדרת MCP Server בסיסי (Filesystem) לא דורשת קוד, רק עריכת קובץ הגדרות. נסביר בדיוק איך.

**הגדרת MCP Server לקבצים:**

ב-Claude Desktop, הולכות/ים ל-Settings (Cmd+, ב-Mac).

> **📸 [IMAGE: Claude Desktop — Settings פתוח, לשונית Developer]**

לוחצות/ים על "Developer". רואות/ים שדה לעריכת קובץ ה-MCP config. לוחצות/ים "Edit Config".

נפתח קובץ JSON. מחליפות/ים את כל התוכן בזה:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/YOUR_USERNAME/Documents",
        "/Users/YOUR_USERNAME/Desktop"
      ]
    }
  }
}
```

מחליפות/ים YOUR_USERNAME בשם המשתמש/ת שלכם/ן ב-Mac. שומרות/ים. מפעילות/ים מחדש את Claude Desktop.

> **📸 [IMAGE: Claude Desktop — קובץ MCP config פתוח ב-TextEdit עם ה-JSON]**

עכשיו Claude Desktop יכול לקרוא ולכתוב קבצים מהתיקיות שציינתם/ן.

```
עובדה חביבה: MCP הוא תקן פתוח שפרסמה Anthropic בנובמבר 2024.
מאז, מאות חברות ומפתחות/ים יצרו MCP servers.
כל שירות עם API יכול להיות MCP Server.
```

# חלק ג׳: n8n, האוטומציה שרצה לבד

עד כאן, ב-Claude Desktop, בנינו אייג׳נט שמכיר אתכם/ן, זוכר הוראות, וניגש לקבצים. הוא מעולה. יש לו רק מגבלה אחת: הוא מחכה לכם/ן.

אתם/ן פותחים, אתם/ן כותבים "תריץ", אתם/ן שם. ברגע שתצאו, הוא ישן. זה לא אוטומציה. זה כלי מאוד חכם עם קליק ידני.

אייג׳נט אמיתי רץ לבד.

## n8n: מה זה ולמה בחרנו בזה

> **n8n**: פלטפורמת אוטומציה ויזואלית שמאפשרת לחבר בין שירותים ולהריץ AI agents על לוח זמנים, בלי לכתוב קוד. עובד בדפדפן, אין מה להתקין.

אם Claude Desktop הוא שותף/ה שעובד/ת לידכם/ן כשאתם/ן שם, n8n הוא עובד/ת שמגיע/ה לעבודה לבד בכל בוקר ב-8:00 ושולח/ת לכם/ן דוח עד שתגיעו.

המנגנון הוא workflow: שרשרת של steps שמתחילת ב-trigger (מה מפעיל) ועוברת דרך actions (מה עושים). כל step הוא "node" ויזואלי על קנבס. מחברות/ים אותם בקווים.

n8n בחרנו כי:
- עובד בדפדפן לגמרי, אין התקנה
- יש בו AI Agent node מובנה עם תמיכה ב-Claude
- יש בו מעל 400 integrations מוכנות
- הגרסה ה-cloud בחינם לטריאל של 14 יום
- open-source — אם רוצות/ים self-hosted, חינמי לגמרי

```
עובדה חביבה: n8n מריצה מעל 100 מיליון workflow executions בחודש.
זה לא כלי ניסיוני — זה infra שארגונים גדולים מסתמכים עליו.
```

## הקנבס: מה רואים

לוחצות/ים "New workflow". נפתח קנבס ריק עם node אחד: "When clicking Test workflow". זהו ה-trigger הידני לטסטינג.

> **📸 [IMAGE: n8n Canvas ריק עם Manual Trigger node במרכז]**

לפני שממשיכות/ים, שנו את שם ה-workflow. לוחצות/ים על "My workflow" בראש, ורושמות/ים "Morning Briefing Agent".

כל workflow מורכב מ:
**Trigger**: מה מפעיל. Manual (ידני לטסטינג), Schedule (לוח זמנים), Webhook (אות מחוץ).
**Nodes**: כל פעולה שה-workflow מבצע. כל node עושה דבר אחד.
**Connections**: הקווים שמחברים node ל-node. הם קובעים את הסדר.

## Node ראשון: ה-AI Agent

לוחצות/ים על + מימין ל-trigger node. נפתח חיפוש. כותבות/ים "AI Agent". לוחצות/ים.

> **📸 [IMAGE: n8n — חיפוש nodes, "AI Agent" מודגש בתוצאות]**

ה-AI Agent node נוסף לקנבס ומחובר אוטומטית ל-trigger. לוחצות/ים עליו לפתוח את ה-configuration panel בצד ימין.

> **📸 [IMAGE: n8n — AI Agent node על הקנבס, configuration panel פתוח]**

**System Message**: זה ה"תדריך" של האייג׳נט. מה הוא עושה, מה הגבולות, מה הפורמט של התוצאה. מדביקות/ים:

```
אתה אייג׳נט הסיכום הבוקרי.

כל פעם שמפעילים אותך:
1. קרא את 10 המיילים האחרונים מ-Gmail שאינם ספאם
2. לכל מייל שדורש תשובה, כתוב: נושא + פעולה נדרשת + עד מתי
3. שמור את הרשימה ב-Google Sheets בגיליון "Daily Briefing", עמודה לתאריך
4. מיילים לידיעה בלבד — סכם בשורה אחת, ללא פעולה

כללים קשיחים:
- אל תשלח שום מייל בלי אישור מפורש ממני
- אל תמחק שום מייל
- אם מייל לא ברור, כתוב "לא ברור" ועבור הלאה
```

> **📸 [IMAGE: n8n — AI Agent configuration panel עם System Message מלא]**

**Model**: לוחצות/ים "+ Add credential", בוחרות/ים "Anthropic Claude".

כאן נכנס ה-API key. זה הדבר היחיד שדורש קצת עבודה, אבל זה פשוט:

**איך מקבלים API key מ-Anthropic:**
- הולכות/ים ל-platform.claude.com
- נרשמות/ים (שימו לב: זה שונה מ-claude.ai — זה ה-developer platform)
- בסיידבר: "API Keys"
- "Create Key", נותנות/ים שם
- מעתיקות/ים מיד — מוצג רק פעם אחת

> **📸 [IMAGE: platform.claude.com — עמוד API Keys עם כפתור Create Key]**

> **📸 [IMAGE: n8n — Anthropic credential dialog עם שדה API key]**

מכניסות/ים את ה-key, לוחצות/ים Save. עכשיו n8n יכול לדבר עם Claude.

**Max Iterations**: שנו ל-10. זה מניח שהאייג׳נט לא יריץ יותר מ-10 צעדים בריצה אחת.

## Memory Node: כי אייג׳נט שלא זוכר זה סיזיפי

בלי זיכרון, כל ריצה מתחילה מאפס. האייג׳נט לא יודע מה סיכם אתמול, לא יכול להגיד "חדש מאתמול", יחזור על אותו עבודה שוב ושוב.

מוסיפות/ים "Simple Memory" node ומחברות/ים אותו ל-Memory port של ה-AI Agent.

> **📸 [IMAGE: n8n — Simple Memory node מחובר ל-Memory port של AI Agent]**

לחלופין, לזיכרון חזק יותר שנשמר בין sessions שונות: מוסיפות/ים שורה ל-Google Sheets בסוף כל ריצה עם סיכום קצר של מה נעשה. בתחילת כל ריצה, קריאת 5 השורות האחרונות. זה persistent memory בלי מסד נתונים.
