Executive Summary

DubleSlash is a methodology engine that solves AI session continuity — the context that breaks every time a session ends, a tool switches, or a teammate picks up the work. When a user invokes // inside any AI tool, DubleSlash injects the current project context automatically: the phase, the decisions made, where the session left off. No re-briefing. No cold starts.

On the desktop, DubleSlash lives as a persistent pill — always on, system-wide. Type // from any AI tool and the pill opens instantly: APEX surfaces your task landscape across projects, you pick one, context is injected, and the session begins. Behind the scenes, Echo and Prism sync your sessions to the shared cloud automatically — no manual configuration, no sharing step. The web app is the team's brain: a shared context management cloud where every individual's sessions, decisions, artifacts, and phase transitions become collectively visible, searchable, and continuable. Pick up where a teammate left off. See how every thread converges into one project. DubleSlash replaces the stack — Jira, Obsidian, scattered AI configurations — with one methodology-native system that every person on the team feeds into just by doing their work.

DubleSlash isn't a memory tool — it's a methodology engine. Context is organized by project, phase, and design process. Agents trained on the Fish Model know what's relevant for each session type, pull only the right context, and inject it at the right moment.

What Makes This Special

Methodology Engine

Not a memory tool. Context is organized by Fish Model phase and archetype — not stored as a flat log. The system knows what matters now.

Zero Cold Starts

Sessions pick up mid-thought. Not because they remembered everything — because the right things were organized and ready.

The Team's Brain

Every session anyone runs feeds the shared cloud automatically. The web app is where individual work becomes collective intelligence — pick up a teammate's session, trace every decision, see how the whole project converges. Replaces Jira, Obsidian, and scattered AI configs.

Two-Runtime Model
Runtime 1 — Desktop
Local · macOS menu bar · Always-on
macOS 13+
  • Shell: Electron or Tauri (TBD by M1 tech spike)
  • Ollama: Runs on-device. Handles onboarding context generation + session summarization. Not used for live AI sessions.
  • Local state: SQLite — contexts, tasks, session summaries, sync state
  • // hotkey: Registered system-wide. Activates context popup within 500ms.
  • Background sync daemon: Pulls from Supabase on app open. Pushes node updates within 60s of session completion. Off the main thread — never blocks //.
  • Adapter interface: Claude Desktop (clipboard + AppleScript), Cursor (.cursorrules), VS Code (extension API). Common ContextAdapter interface.
  • Auth: Optional. Local-only mode needs no account. JWT in macOS Keychain for team sync.
Runtime 2 — Web App
Cloud · Browser · No install
Vercel + Supabase
  • Frontend: Next.js, deployed on Vercel
  • Database: Supabase Postgres — contexts, nodes, artifacts, sessions, team
  • Auth: Supabase Auth — email + magic link at V1; SSO (Google, GitHub) at V1.5. JWT in HTTP-only cookie.
  • Storage: Supabase Storage — artifacts, context .md files
  • Realtime: Supabase Realtime — live Node Map updates within 60s of session sync
  • Source of truth: All project state. Desktop app syncs to/from this.
  • Purpose: The team's shared context management cloud — every session anyone runs feeds it automatically via Echo + Prism. Any team member can see each other's contexts, pick up a colleague's session, and trace the full project arc. Replaces Jira + Obsidian + manual AI configuration.
  • Access: All team members — browser, no install required. Desktop pill syncs to and from this; web app is the canonical team view.
Session Data Flow
User types //start in menu bar
→ Desktop popup reads local SQLite
→ User selects task — context pre-loaded in task detail
→ Adapter injects context .md into host tool (Claude / Cursor / VS Code)
→ AI session runs — operator agent (Dora / Sol / Bran / May) active
→ Session ends (user closes Claude or finishes)
→ Guard: scans session content for GDPR flags / PII / injection
→ Echo: captures session → pushes to local SQLite (non-blocking)
→ Ollama: summarizes session → generates brief update
→ Dedup check: contextId + sessionHash against local SQLite
→ Write to local SQLite (non-blocking — does not delay next //)
→ Async push to Supabase cloud (within 60s, with consent)
→ Supabase Realtime → Node Map dot updates within 10s
→ Prism: similarity pass across all session content for cross-context patterns
→ Apex: updates priority queue — surfaces next 2 most important items

Drill-down Drawer
Right-side drawer · Triggered by card click in Snapshot view
Drawer · 7 sections
  • 1. Recipe: Stream checklist for archetype × phase — done (✓ green), in-progress (● phase color), pending (○ dim), deferred (— strikethrough + reason). Budget estimate (time range for archetype × phase).
  • 2. Handoff: Locked decisions (bordered chips), open items (yellow, checkbox-resolvable), confidence score (color-coded), artifact paths, emitter → receiver. If no handoff: "No handoff yet."
  • 3. Artifacts: Two-column grid grouped by phase bucket. Status badges: ✓ locked / ● draft / ○ not started.
  • 4. Decision log: Timestamped list — date, decision text, author. Empty state: "No decisions logged."
  • 5. Session history: Compact list — date · tool · model. One-line session summary below each. Most recent first.
  • 6. Tasks: Full task list with checkboxes. Agent chip row below (agents that have worked on this context).
  • 7. Forward action (sticky bottom bar): "→ Continue in {tool}" / "→ Advance to {phase}" / "Resolve blocker" / "→ Emit handoff" — CTA changes based on context state.

General UI Principles

Visual Language

  • Dark mode by default. Light mode toggle in profile settings.
  • Monospace font for: .md previews, reasoning entries, method names, capability codes, invocations, all 8–10px labels.
  • Phase colors: Explore (ds-explore · warm orange), Solidify (ds-solidify · purple), Build (ds-build · blue), Ship (ds-ship · teal).
  • Archetype colors: Nemo = Ship/teal, Tuna = Solidify/purple, Salmon = Explore/orange, Willy = Build/blue.

Motion + Interaction

  • Card hover expansion: 150ms transition-all.
  • Drawer slide-in: 200ms transition-transform.
  • Signal strip filter: 150ms transition-opacity. No other animation.
  • All destructive actions (delete context, remove team member) require explicit confirmation dialog before executing.

Domain Requirements

Data Privacy & GDPR

  • All context data stored locally by default; nothing leaves the device without explicit user-initiated push consent.
  • Cloud sync requires one-time opt-in per device; consent is re-confirmable and revocable at any time.
  • User data deletion requests completed within 30 days; full data export available in .zip format on demand.
  • Team sync logs include actor, timestamp, and action type for audit trail; accessible to team admins.
  • No session content sent to third-party analytics; only anonymized usage telemetry (opt-out available).
  • Guard agent scans every session and handoff for PII, credentials, and injection before any outbound sync.

Local-First Architecture

  • Desktop app operates fully offline; // flow, Ollama inference, and context access function without internet.
  • Cloud sync is additive — app degrades gracefully to local-only mode when sync is unavailable.
  • Ollama model downloaded once; subsequent inference requires no network calls.
  • All captures are intent-triggered — no ambient collection sidesteps MDM and privacy policy concerns.

macOS Platform

  • Minimum macOS 13 (Ventura). Notarized + signed by Apple Developer ID at V1 launch.
  • Menu bar app pattern: no Dock icon by default; accessible via menu bar icon or global // hotkey.
  • Ollama bundled or auto-installed as dependency during onboarding; user prompted if not present.
  • No background processes requiring MDM approval — capture is intent-triggered, not ambient.
  • JWT tokens stored in macOS Keychain; never in plaintext on disk.

B2B Multi-Tenant

  • Each team workspace is isolated; cross-workspace data access is not possible at the data layer.
  • Role-based access: Individual (full read access to all team contexts + create/own contexts; no user or billing management), Admin (full access + user management + billing).
  • Billing at team level; seat counts managed by Admin role.
  • Business model: B2B, Obsidian motion — individual ICP, company pays at team scale. Free solo, Pro $12/mo, Team $24/seat.
