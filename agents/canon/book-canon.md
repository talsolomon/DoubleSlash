# DubleSlash Agent Book Canon

The full reference library embedded in every agent's expertise. These are not a reading list — they are the theoretical and practical foundations that agents cite, apply, and recommend from within their methods.

Organized by domain. Agent-specific mappings are in `book-canon-by-agent.md`.

---

## Foundations of UX & Interaction Design

- **The Design of Everyday Things** — Donald Norman *(the bible; affordances, mappings, feedback, constraints, mental models — agents reference this constantly)*
- **About Face: The Essentials of Interaction Design** — Alan Cooper et al. (4th ed.) *(Goal-Directed Design; personas; interaction models; Dora's GDD reference)*
- **The Inmates Are Running the Asylum** — Alan Cooper *(the argument for design-first; backstory for GDD)*
- **Don't Make Me Think** — Steve Krug *(web usability; cognitive load; Krug's first law — applied in every UV and WF)*
- **The Elements of User Experience** — Jesse James Garrett *(five planes model; vocabulary for design conversation)*
- **Designing for the Digital Age** — Kim Goodwin *(Cooper-style GDD in full; detailed methodology reference)*
- **Universal Principles of Design** — Lidwell, Holden & Butler *(125 principles; reference during HS and WF)*
- **Designing with the Mind in Mind** — Jeff Johnson *(applied cognitive psychology for UI; perception, memory, attention)*
- **Laws of UX** — Jon Yablonski *(Fitts, Hick, Miller, Jakob's Law, etc.; quick empirical reference)*
- **100 Things Every Designer Needs to Know About People** — Susan Weinschenk *(behavioral science applied to design)*
- **The UX Book** — Rex Hartson & Pardha Pyla *(comprehensive process reference)*
- **Emotional Design** — Donald Norman *(visceral, behavioral, reflective levels; deeper read than DOET)*
- **Conceptual Design for Interactive Systems** — Avi Parush
- **An Introduction to Human Factors Engineering** — Wickens et al. *(ergonomics and human factors foundations)*
- **Well-Designed** — Jon Kolko *(synthesis and sensemaking; building the product stack)*
- **The Shape of Design** — Frank Chimero *(design philosophy; how and why of form)*

## Quick Reference by Situation

**"I need to understand this user problem better"** → Just Enough Research → Interviewing Users → When Coffee and Kale Compete

**"I need to frame this as a job-to-be-done"** → Competing Against Luck → When Coffee and Kale Compete → Continuous Discovery Habits

**"I need to pick one shape"** → Shape Up → Good Strategy Bad Strategy → Playing to Win

**"My AC is fuzzy"** → Outcomes Over Output → Lean Analytics → Measuring the UX

**"I need to justify this design decision"** → Articulating Design Decisions → About Face → Laws of UX

**"The design needs to be more emotionally engaging"** → Designing for Emotion → Seductive Interaction Design → Hooked

**"My UI looks wrong but I don't know why"** → Refactoring UI → Universal Principles of Design → The Non-Designer's Design Book

**"I need to make a business case for this work"** → Outcomes Over Output → Lean Analytics → Cost-Justifying Usability

**"I need to think about ethics and privacy"** → Dark Patterns → Future Ethics → Data and Goliath

**"I need to understand our product strategy"** → Good Strategy Bad Strategy → Obviously Awesome → Playing to Win

**"My code is getting complicated"** → A Philosophy of Software Design → Clean Code → Refactoring

**"How do I measure if this release worked?"** → Accelerate → Lean Analytics → Measuring the UX

**"I want to understand cognitive load and memory"** → Thinking, Fast and Slow → Designing with the Mind in Mind → Laws of UX

**"I'm designing an AI feature"** → Machine Learning for Designers → Human + Machine → Future Ethics
